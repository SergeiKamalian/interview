# 18 — Achieved level + talent pool

Status: ✅ done (18.1–18.10 — achieved level + talent pool по стеку + backfill + UX кнопка-счётчик/модалка)

## Зачем

Сейчас итоговая рекомендация (`hireRecommendation`) считается только от того, насколько
хорошо кандидат ответил на **заданные** вопросы (см. `scoring.service.ts` →
`mapHireRecommendation`). Целевой уровень интервью (`interviews.level`) в скоринг **не входит** —
он влияет только на подбор вопросов при создании интервью.

Из-за этого теряется ценный сигнал: кандидат пришёл на **lead**, не прошёл (вопросы сложные),
но реально **тянет middle** — он плюс-минус понимал материал. Компании это важно: им сейчас нужен
сильный lead, но позже понадобится middle — и тогда этого человека можно сразу предложить.

## Что делаем

Вводим отдельную ось **achieved level** («демонстрированный уровень») — максимальный уровень,
который кандидат реально показал, **независимо** от целевого уровня интервью. Плюс **talent pool**:
при создании нового интервью на уровень X подсвечиваем прошлых кандидатов с `achievedLevel >= X`.

## Ключевая идея расчёта

У каждого `interview_questions.level` уже есть уровень (`junior|middle|senior|lead`) и `max_score`,
а per-question баллы уже считаются. Группируем баллы по уровню вопроса и определяем максимальный
**подтверждённый** уровень.

- **Evidence-режим** (в интервью есть вопросы разных уровней): идём по лестнице
  `junior → middle → senior → lead`; achievedLevel = высший уровень, по которому средний
  нормализованный балл ≥ порога (`ACHIEVED_LEVEL_PASS_RATIO`, default 0.65), при условии что все
  нижние присутствующие уровни тоже взяты. `method = evidence`.
- **Estimate-режим** (все вопросы одного уровня — нет нижнего сигнала):
  - прошёл порог → achievedLevel = этот уровень (`method = evidence`, т.к. уровень напрямую
    проверен);
  - не прошёл → achievedLevel = null + `estimatedLevel` на уровень ниже (грубая оценка по проценту),
    `method = estimate`, с пометкой добавить «калибровочные» вопросы нижнего уровня для точности.

**Инвариант:** achieved level — это **дополнительная** ось. Существующий скоринг/рекомендация
(`mapHireRecommendation`, golden calibration) НЕ меняется.

## Модель данных

- `final_evaluations` (одна строка на попытку) — место для `achieved_level` + `achieved_level_method`.
- talent pool матчит одного человека между интервью по `candidates.email` в рамках `company_id`
  (строка `candidates` создаётся под каждое интервью отдельно, unique по `interview_id + email`).
